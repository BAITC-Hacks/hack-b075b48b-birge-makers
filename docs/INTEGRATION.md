# Анализ переданного комплекта интеграции

Документ «Подключение интерфейса к Birge Explain» прочитан полностью: 257 строк, разделы 1–10. Он принят как описание HTTP-контракта существующего агента, а не как исходный код самого агента.

## Основные различия с прежним сайтом

| Раньше | Сейчас |
|---|---|
| Каталог и подбор в браузере | Справочники и выдача через API |
| Жёстко заданные даты | calendar_coverage из GET /catalog/options |
| Локальные шаблоны объяснений | card.explanation и meta_explanation сервера |
| Локальный anon_name | API card.name |
| event, hours | event_format, duration_hours |
| Только положительный бюджет, дробные часы | Бюджет от 0, целые часы от 1 |
| no_category | API no_category_in_city, отдельное представление |
| Пересекающиеся причины | Первая причина из rejection_stats |
| Работа из file:// | Frontend HTTP-сервер с /api proxy |
| Технические исключения локального алгоритма | HTTP, сеть, тайм-аут и неверный конверт |

Дизайн, типографика, локальные оптимизированные изображения, доступные подписи полей и три языка интерфейса сохранены. Старый алгоритм архивирован отдельно, скрытого fallback нет.

## Что пока нельзя подтвердить

В переданной папке был только README. Упомянутые им `src/api/birge.js`, `vite.config.example.js`, `examples/*.json` и сам backend не обнаружены в текущем проекте или рядом с документом. Поэтому HTTP-клиент реализован по документированному контракту; он не представлен как скопированный готовый файл.

Проверка живого агента и последовательности HK-44923 → HK-29829 → HK-27222 ещё не выполнена. Реальная проверка HK-90012 на 14/15 ноября также требует backend и его текущего каталога. Тестовая площадка в автоматическом тесте имеет отдельный идентификатор TEST-VENUE.

Для завершения нужны путь/репозиторий backend и, желательно, комплект frontend-integration с реальными примерами ответов. Нужно сопоставить точную структуру evidence/rejection_stats и поддержку локализации, запустить backend, проверить health и повторить сценарии из его examples. Подготовка индекса и модельные ключи остаются на стороне backend.

## Проверено сейчас

10 автоматических тестов контракта/proxy и сквозная проверка в Chrome через реальный HTTP proxy с явно тестовым backend. Они подтверждают интеграцию интерфейса с описанным протоколом, обработку ошибок и отмены; не подтверждают работоспособность отсутствующего агента.
