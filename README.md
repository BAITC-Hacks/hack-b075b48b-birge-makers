# birge — интерфейс Birge Explain

Премиальный интерфейс подбора подрядчиков подключён к HTTP API Birge Explain. Форма получает справочники и календарь с backend, отправляет заказ и показывает до трёх карточек в порядке ответа. Noto Serif используется только в коротких крупных заголовках; Noto Sans — в интерфейсе, ценах и объяснениях.

## Текущее состояние

- HTTP-клиент, frontend-сервер, proxy и интерфейс реализованы.
- Тесты контракта и сквозные проверки Chrome пройдены на явно тестовом backend.
- **Исходники настоящего агента, готовый клиент из комплекта и примеры его ответов не были переданы вместе с инструкцией. Backend на `127.0.0.1:3000` при проверке недоступен. Интеграция с живым агентом ещё не подтверждена.**
- При недоступном backend сайт показывает ошибку соединения. Локальной подмены рекомендаций нет.

## Запуск

Нужен Node.js 22 или новее. Сторонних npm-зависимостей нет, `npm install` не требуется.

1. В папке существующего backend запустите его по собственной инструкции:

   ```powershell
   node --env-file=.env src/server.js
   ```

2. В этой папке запустите интерфейс:

   ```powershell
   npm.cmd run dev
   ```

   Либо:

   ```powershell
   node start-server.mjs
   ```

   На текущем компьютере также работает `powershell -ExecutionPolicy Bypass -File .\start.ps1`: скрипт найдёт установленный Node или проверенный локальный runtime в `.tools/node.exe`. Папка `.tools` не включается в Git.

3. Откройте **http://127.0.0.1:5173**. Открытие `index.html` через `file://` не поддерживает HTTP-интеграцию; страница объяснит, что нужен сервер.

Backend по умолчанию: `http://127.0.0.1:3000`. Для другого адреса настройте переменную **на frontend-сервере**:

```powershell
$env:BACKEND_ORIGIN = 'http://127.0.0.1:3000'
$env:PORT = '5173'
node start-server.mjs
```

`HOST` по умолчанию равен `127.0.0.1`. Пример настроек — `.env.example`. Файл `.env` автоматически не читается: при необходимости запускайте `node --env-file=.env start-server.mjs`.

## Соединение с агентом

```text
Браузер → /api/catalog/options → backend /catalog/options
Браузер → /api/recommend      → backend /recommend
Диагностика → /api/health    → backend /health
```

Proxy снимает префикс `/api`. Браузер обращается к своему origin, поэтому CORS на backend не нужен. `mode: no-cors` не применяется. Ключи моделей и подготовка индекса остаются в проекте backend; frontend не вызывает модель напрямую.

Маршрута `/explain` в обычном сценарии нет: фильтрацию, календарь и объяснение выполняет `/recommend`. Frontend не пересортировывает карточки и не заменяет серверные объяснения собственными.

При публикации запустите этот frontend-сервер за HTTPS reverse proxy либо настройте аналогичный маршрут `/api`. Адрес backend задаётся на сервере; браузер пользователя не должен обращаться к своему `127.0.0.1:3000`.

## Форма и результат

- Города, категории, форматы, языки и `calendar_coverage.start/end` загружаются через API.
- Запрос: `city`, `date`, `event_format`, `category`, `budget`, `duration_hours`, `language`.
- Бюджет — целое число от 0. Пустой бюджет не превращается в 0. Пробелы, запятые группировки и завершающий ₸ преобразуются перед отправкой.
- Длительность — целое число от 1, пустое значение превращается в `null`. Пустой язык — `null`.
- Дата передаётся как календарная строка YYYY-MM-DD без изменения часового пояса.
- Ответ разбирается из JSON внутри `<response>…</response>`. HTML вместо ответа считается технической ошибкой.
- Карточка показывает `name`, `category`, `city`, `price_from_kzt`, `explanation`, `price_note` и `data_flags`.
- Подтверждающие сведения `evidence` доступны в раскрывающемся блоке. Замечания `explanation_limitations` показываются отдельно.
- `meta_explanation` выводится без пересказа. `eligible_count` относится ко всем прошедшим кандидатам; максимум отображения — 3.
- Статусы `matched`, `no_category_in_city`, `no_match` различимы. Причины в `rejection_stats` не складываются как пересекающиеся множества: каждый кандидат учтён по первой причине.
- При изменении полей старый запрос отменяется через AbortController. Запоздалый ответ не заменяет результат нового запроса.
- HTTP 400 отображается рядом с формой; известные поля `error.fields` — под соответствующими полями. Сетевая ошибка, тайм-аут и сбой сервиса отделены от пустого результата.
- Повтор запроса сохраняет введённые условия. Кнопки изменения условий только переводят фокус.
- Текст API вставляется через `textContent`; HTML из имени или объяснения не исполняется.

Интерфейс переводится на қазақша / русский / English. В запросе отправляется `Accept-Language`, но поддержка этого заголовка настоящим backend в переданном документе не гарантирована. **Серверные объяснения отображаются в исходном виде**: frontend не придумывает перевод. Для единого языка всех объяснений backend должен поддерживать локализацию.

## Диагностика

`GET /api/health` доступен разработчику; `ai.ready=false` не блокирует базовую выдачу. Для готовности индекса следуйте инструкции backend и перезапустите его после подготовки. Технические сведения об индексе не добавлены в карточки.

HTTP 502 / `PROXY_ERROR` означает, что proxy не смог связаться с backend. HTTP 504 — тайм-аут. Не нужно менять бюджет или дату для исправления соединения.

## Проверки

```powershell
npm.cmd test
npm.cmd run test:browser
```

Без npm с локальным runtime:

```powershell
.\.tools\node.exe --test test/api.test.mjs test/server.test.mjs
.\.tools\node.exe test/browser.integration.mjs
```

Браузерная проверка требует установленного Chrome. Иной путь можно задать через `CHROME_PATH`. Тест самостоятельно запускает backend с синтетическими контрактными ответами на свободных портах и отдельный скрытый профиль Chrome, а затем закрывает их. Он **не проверяет качество настоящего агента** и не служит резервным режимом сайта.

Проверены: преобразование полей, 0/пустой бюджет, дробные часы, динамические даты, XML-конверт, неизменность порядка, флаги и evidence, три результата, редкая категория, ограничения объяснения, занятая площадка, HTTP 400/500, неправильный ответ, остановка backend, повтор, отмена старого запроса, безопасный вывод текста и мобильная ширина 320 px.

## Основные файлы

- `src/api/birge.js` — HTTP-клиент, разбор конверта, проверка ответа и преобразование заказа.
- `app.js` — загрузка справочников, форма, запросы, карточки и ошибки.
- `form-utils.js` — валидация по серверным справочникам и календарю.
- `result-state.js` — представление серверного результата.
- `server.mjs`, `start-server.mjs`, `start.ps1` — статические файлы и proxy.
- `index.html`, `styles.css`, `i18n.js` — согласованный дизайн и локализация.
- `test/` — тесты; ответы фикстуры явно отделены от рабочего приложения.
- `reference/local-demo/` — архив прежнего локального каталога и алгоритма. Не подключается к сайту и не раздаётся сервером.
- `assets/fonts/` — локальные Noto Serif / Noto Sans и лицензии.
- `assets/IMAGE-NOTES.md` — описание атмосферной иллюстрации.

Сервер раздаёт только разрешённые ресурсы интерфейса. `.env`, исходники server, тесты и архив каталога не доступны через сайт. Бронирование, оплата, заявки и сообщения подрядчикам не добавлялись.
