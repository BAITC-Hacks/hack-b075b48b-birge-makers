# Birge Explain — интерфейс и проверка интеграции

Теперь в проект включён адаптивный интерфейс на **қазақша / русском / English**. Он работает с настоящим каталогом через существующий backend. Нет локального алгоритма подбора, случайной сортировки или скрытой подстановки тестовых карточек при сбое API.

## Запуск

Требуется Node.js 22.13+. Для запуска приложения npm-пакеты не нужны:

```sh
node --env-file-if-exists=.env src/server.js
```

Откройте **http://127.0.0.1:3000/**. Интерфейс и API обслуживаются одним процессом и одним origin: отдельные frontend-сервер и CORS-настройки не требуются. Если старый сервер уже работает, остановите его в его терминале и запустите новую версию.

Если порт занят, настройте `PORT` в `.env` и откройте соответствующий адрес. `HOST` по умолчанию — `127.0.0.1`, то есть локальный доступ.

Для AI-индекса необходимы настройки OpenAI в `.env`. Подготовка выполняется на сервере:

```sh
node --env-file=.env src/prepare.js
```

После подготовки перезапустите сервер. `/health` показывает `ai.ready`. Без готового индекса backend может выдавать структурированные объяснения; интерфейс не объявляет их результатом нового вызова LLM. Сетевые вызовы моделей во время обычного подбора не нужны: используется сохранённый индекс. Как настроить модели — в [основном README](README.md).

## Контракт и состояния

- `GET /catalog/options` заполняет форму реальными городами, категориями, форматами и языками. Минимальная/максимальная дата берётся из `calendar_coverage`.
- `POST /recommend` получает числовой `budget`, целочисленную длительность или `null`, язык или `null`. Дата передаётся строкой `YYYY-MM-DD` без сдвига часового пояса.
- Реальный ответ — `application/xml`: JSON внутри `<response>...</response>`. Клиент разбирает именно эту оболочку.
- При `matched` показываются 1–3 карточки в **том порядке, который вернул сервер**. Для малого результата показывается `meta_explanation`.
- `no_category_in_city` и `no_match` имеют разные заголовки и пояснения.
- Сетевой сбой — отдельная техническая ошибка с кнопкой повтора, а не отсутствие подрядчиков. При недоступности справочника форма заблокирована, есть отдельный повтор загрузки.
- Новая отправка или изменение поля отменяет старый запрос. Дополнительный счётчик поколения защищает от старого ответа даже при игнорировании `abort` транспортом.
- `explanation`, `meta_explanation` и `price_note` показываются дословно. Это текст на русском языке из каталога; он явно отмечен `lang="ru"`, а интерфейс предупреждает о языке источника. **Перевод AI-объяснений на казахский/английский не реализован**, чтобы не выдавать изменённый клиентом текст за ответ сервера.
- Подписи формы, состояния, навигация и названия справочников переведены на три языка. API всегда получает канонические значения каталога, а не перевод из интерфейса.
- Календарь датасета ограничен 23.09–31.12.2026. Стартовая цена — не итоговая смета. Синтетические профили и заполненные цены обозначаются.

## Мобильная версия и доступность

- Адаптивные сетки, одна колонка на узких экранах, отсутствие горизонтального скролла начиная с 320 px.
- Длинные названия переносятся; элементы формы не выходят за контейнер.
- Кнопки/поля имеют высоту не менее 44 px; текстовые поля на телефоне — 16 px.
- Видимый `:focus-visible`, ссылка пропуска к форме, `label`, `fieldset/legend`, `aria-invalid`, `aria-describedby` и `aria-live`.
- При ошибке фокус переходит к первому неверному полю, после результата — к заголовку выдачи.
- Состояние загрузки обозначено `aria-busy`; учитывается `prefers-reduced-motion`.
- Данные сервера добавляются через `textContent`/текстовые узлы. Нет исполнения HTML из ответа.

## Изображения, шрифты и скорость

При начале работы в репозитории не было локальных изображений и файлов шрифтов, поэтому переиспользовать их было невозможно. Добавлена собственная локальная **векторная** иллюстрация, а не загруженные фотографии. Hero имеет варианты **640 / 960 / 1536 px**, `srcset`, `sizes`, `width/height`, `fetchpriority="high"` и `loading="eager"`. SVG сохраняет чёткость без тяжёлых растровых файлов. Размеры файлов можно проверить в `public/assets/`.

Шрифты не загружаются с внешних сайтов: используются локальный Segoe UI через `@font-face` с `font-display: swap` и системные fallback-шрифты. Нет Google Fonts, CDN, frontend-фреймворка или сборки, необходимой для запуска.

Публичные файлы выдаются по явному списку. `.env`, каталог, AI-индекс и серверные JS недоступны через static-маршруты. Ключи остаются в backend. CSP ограничивает скрипты, шрифты, изображения и соединения своим origin.

## Как воспроизвести проверки

Без API-вызовов OpenAI:

```sh
node --test
```

Для браузерных проверок установите dev-зависимости:

```sh
npm ci
npm run test:ui
```

В Windows PowerShell можно использовать `npm.cmd`. На Windows тесты по умолчанию используют установленный Microsoft Edge. Можно указать `PLAYWRIGHT_CHANNEL=chrome` в окружении тестового процесса для установленного Chrome. На Linux/macOS установите браузер командой `npx playwright install chromium`; по умолчанию используется Chromium.

Тесты поднимают отдельный настоящий backend на **127.0.0.1:3107**, не останавливая пользовательский сервер на 3000. Порт 3107 должен быть свободен. JSON-отчёт — `reports/ui-results.json`, скриншоты — `reports/ui-*.png`. Если среда исполнения ограничивает запуск или завершение процессов браузера Windows, запускайте тесты в обычном локальном терминале с доступом к этим операциям.

### Проверки с настоящим backend

Используется `src/server.js`, каталог из `data/contractors.json` и доступный локальный AI-индекс; ответы `/recommend` не подменяются:

- бюджет-число и `null` для необязательных полей;
- 1, 2 и 3 карточки;
- три статуса результата;
- исключение занятой площадки на 14 ноября и выдача той же площадки на 15 ноября;
- дословное совпадение объяснений DOM с ответом API;
- порядок ID и повторяемость результата;
- три языка интерфейса и казахские символы;
- ошибки полей, фокус, клавиатура;
- 320, 390, 768 и 1440 px: переполнение и автоматическая проверка axe по WCAG 2 A/AA и 2.1 AA;
- локальные hero-изображения и недоступность секретных файлов по HTTP.

### Проверки с имитацией ответов/сети

Подмена существует **только в Playwright-тестах**, в приложении её нет:

- сетевой сбой `/recommend`, техническая ошибка, отсутствие карточек, затем повтор к реальному backend;
- отказ `/catalog/options`, блокировка полей и повтор к реальному backend;
- искусственно задержанный старый ответ, который не должен заменить более новый реальный результат;
- вредоносная HTML-строка в объяснении и очень длинное казахское имя: текст не исполняется и не расширяет страницу.

Автоматическая проверка axe не заменяет ручной аудит со скринридером. Проверены размеры в настольном Edge, **не физические мобильные устройства и не Safari/Firefox**. Браузерные тесты используют backend с сохранённым индексом, а не вызывают LLM заново. Для отдельной реальной проверки OpenAI:

```sh
node --env-file=.env scripts/verify-ai.js
```

Эта команда расходует квоту. В рамках добавления интерфейса новые вызовы моделей не требуются.

## Ручной сценарий

1. Откройте страницу и выберите язык.
2. Заполните: Алматы, 14.11.2026, корпоратив, ведущий, 1 500 000 ₸, 4 часа, русский.
3. Нажмите кнопку подбора. Должны появиться HK-44923, HK-29829, HK-27222 в таком порядке.
4. Для одной карточки: Астана, флорист, корпоратив, та же дата и бюджет; длительность/язык оставить пустыми.
5. Для отсутствующей категории: Астана, национальный ансамбль.
6. Для отсутствия подходящих: Алматы, ведущий, бюджет 1 ₸.
7. Повторите на ширине 320 px, пройдите форму клавишей Tab.

## Что не подключено

Нет бронирования, оплаты, заявок, уведомлений подрядчикам, личного кабинета, публичного деплоя и синхронизации с живыми календарями. Эти возможности не изображаются как работающие. Интерфейс выполняет только подбор и показ объяснений.
